# src/components/settings — the settings dialog

The settings dialog and the folder-grant form. Also owns `src/lib/`'s `sandbox-*.tsx`, `cluster-scope.ts`, `env-vars.tsx`, `permission-settings.tsx`, `provider-credentials.tsx` and `settings-tab.ts`. The webview-wide rules, security invariants first, are [`src/CLAUDE.md`](../../CLAUDE.md), which also covers the color-scheme picker (*Theming & storage*).

**The Settings dialog** is `components/settings/settings-dialog/`, exporting `SettingsDialog` alone: a `PanelDialog` (`primitives/dialog.tsx`) with vertical tabs beside its pane. It opens on General (`general.tsx`), which holds the Mode picker (`color-scheme-picker.tsx`). A pane is a column of `Group`s (`group.tsx`): a heading, optional lede, info control (`InfoPopover`) and action, over its body. A pane that is one list is an `Intro` instead: its lede over the list, which the pane's heading names. A hidden tab's pane unmounts, so its watches run only while it is selected. A pane selects another tab through `useSelectSettingsTab()` (`src/lib/settings-tab.ts`).

**Clusters** (`clusters.tsx`) lists `useClusters()`'s kubeconfig clusters, then the archived ones (no longer in the kubeconfig), hidden when there are none; nothing draws before the `Bookmark`. Every string from a cluster goes through `VisibleText`. Its actions are `ClusterSyncPanel`'s mutations (`src/lib/cluster-mutations.ts`), with no confirm; each row redraws from the watch.

**Connectors** (`connectors.tsx`) is one list, by name, of `useConnectors()`'s services (`src/lib/connectors.tsx`), drawing nothing before each watch's first frame. **ChatGPT, OpenRouter, AWS, GitHub and Google are real rows**, their actions following the connection's phase. One `failureText`, a `Record` over `ConnectorFailure`, gives every failure its line, so a new one fails the build. ChatGPT's first connection is confirmed once, in the window that connected (`kstack:chatgpt-plan-confirmed`; the window's pending sign-in is `sessionStorage`'s, so it outlasts the pane). Disconnect is confirmed: OpenRouter's and GitHub's credential stays live there, AWS's session until it expires. AWS's detail is the ARN; GitHub's row draws its code. The other rows are placeholders: a connected one with a disabled menu, any other with a disabled *Coming soon*. Every string goes through `VisibleText`.

**Providers** (`providers.tsx`) lists `useProviderCredentials()`'s providers, set up while signed, then `PROVIDERS`, set up while `useModels()` serves them; nothing draws before both. Null `keyVariable` gets *Connect*, no key UI. *Configure…* and *Set up* open `provider-setup-form.tsx`. **The webview's one typed secret**: the form holds the key, and the hook sends it through `client.mutation(...).toPromise()`, never `useMutation`, whose state would keep it. → [record](../../../docs/security/2026-11-20-saved-provider-keys.md).

**Memory** (`memory.tsx`) shows one scope: *Every cluster* (the default) or a cluster, picked from the kubeconfig's, then the archived, by `ScopePicker` (`scope-picker.tsx`) over `useScope`. It reuses the memory popover's parts (`src/components/cluster/CLAUDE.md`, *Memory*), keyed on the scope. Every cluster's notes ride on the window's cluster's watch, else the first record's. Placeholders, marked in code: local instructions, no note counts, and a disabled *Clear* awaiting `memoryClear`.

**Environment** (`environment.tsx`) is the user's variables for one scope (`useEnvVars(clusterID)`), picked as Memory's is. A variable names the commands it reaches (`EnvVarTarget`); a refused one is drawn on its own row with its reason. The form is keyed on the scope.

**Monitoring** (`monitoring.tsx`) is a placeholder, *Coming soon*, until monitoring has settings of its own.

**Sandbox** (`sandbox.tsx`) is the status card (`sandbox-status.tsx`), then one `Group` (`group.tsx`) per section in a file beside it: `sandbox-folders.tsx`, `-network.tsx` (`useSandboxCloudAccess`, read-only), `-path.tsx`, Executables, `-environment.tsx`; *Try a command* opens `sandbox-console.tsx`. With `available: false`, the card alone, and Permissions says why nothing applies. Placeholders, each disabled or marked *Coming soon*: the status switch, the console's *Run*, the tools/shell/system folder groups, Environment but *Custom*, which lists every cluster's variables for sandboxed commands (`useEnvVars(null)`) and edits none. Each hook re-asks its query after a mutation, and on focus where another window can change it. Every user, sidecar or command string goes through `VisibleText`.

- **`PATH`** (`useSandboxPath`, shared by Folders' switches and the PATH card). Entries keep whitespace and spell trailing characters, since Include approves the folder drawn. Include sends the drawn `target`, so a refresh that moved it refuses. While the fault is set, what commands search comes from `sandboxPathResolved`, never from the list's length. → [ADR: `PATH` is the login shell's, filtered and frozen](../../../docs/adr/2026-10-02-path-is-the-login-shells-filtered-and-frozen.md).
- **Executables** (`useSandboxExecutables` in `src/lib/sandbox-executables.tsx`) over the `sandboxExecutablesWatch` gauge. The probe mutation answers at once and the watch carries the end. After a press, *Probe again* holds until the watch's `probes` count passes the one seen at the press — the answer and the frame race, and a gauge can fold a short probe's start into its end.
- **Folders** (`useSandboxFolders(chatID?)` in `src/lib/sandbox-folders.tsx`; `grant` runs under `chatGrantsContext`). **`FolderGrantForm`** (`components/settings/folder-grant-form.tsx`) is the one form a folder is granted from, here and in the transcript; it sends the path exactly as typed. Access and Remove are disabled while `rulesHeld`. → [path grants](../../../docs/security/2026-10-04-path-grants.md).
- **Permissions** (`permissions.tsx` and the `permission-*.tsx` beside it; `usePermissionSettings` in `src/lib/permission-settings.tsx`). `field.tsx`'s `Select` spells each option out. **The hook alone spells the wire's dotted keys** (`permissions.defaultMode`, `.modes`, `.rules`); everything else uses `PermissionField`. While the file holds values Kstack cannot read, that field's edits are disabled and *Discard what Kstack cannot read* (`permissionDiscardRefused`) sits behind a confirm naming them. *Clear* acts on a context's own entry, never a pattern it matches. **An edit adds the new rule, then removes the old id only if the add was taken**; a verdict holds under any rule order and Deny wins. Placeholders are marked `// Placeholder: awaits …`. → [the permissions engine](../../../docs/security/2026-10-02-the-permissions-engine.md).
