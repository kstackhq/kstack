# src/components/shell — the app's frame

The app bar, both sidebars, the window frame and its controls, and the startup gate, with `layouts/app-layout.tsx` and the `src/lib/` modules behind them (`window-drag.ts`, `focus-trap.ts`, `persisted-width.ts`, `right-sidebar.tsx`). The omnibox's cluster picker and popovers are the cluster guide's ([`../cluster/CLAUDE.md`](../cluster/CLAUDE.md)). Read it before changing any of them. The webview-wide rules, security invariants first, are [`src/CLAUDE.md`](../../CLAUDE.md).

## Startup

**`ReadyGate` (`src/components/shell/ready-gate.tsx`) draws `AppMark`** at 48px, centred, in every state. `AppMark` draws `src/assets/icons/`'s light or dark app icon, one per scheme; those are `make generate-icons`' copies of `src-icons/`. `index.html` carries a static copy of the same mark inside `#root`, so first paint and React's first commit show the same thing in the same place — keep them matching. It also draws a 48px `data-tauri-drag-region` strip over its top edge, so the window drags before the app bar mounts; `index.html`'s static copy carries the same strip.

## Window layout

`layouts/app-layout.tsx` is the one place the shape is expressed: a 48px app bar over a row of the left sidebar, `<main>` and the right sidebar. Nothing is fixed-positioned. Traps:

- **The app bar** (`components/shell/app-bar/`, exporting `AppBar` alone; `app-bar/bar.tsx`) is a `deep` Tauri drag region; controls inside stay clickable via Tauri's hit test, and the omnibox opts out with `data-tauri-drag-region="false"`. A press that drags never reaches the webview as a click, and Base UI's popovers dismiss on an outside click, so the bar's `onPointerDown` (`dismissPopupsOnWindowDrag`, `src/lib/window-drag.ts`) clicks the pressed element itself. `startsWindowDrag` there mirrors Tauri's drag hit test; diff it against `drag.js` on a Tauri upgrade. On macOS it reserves the native traffic lights with `TrafficLightGutter` (`traffic-light-gutter.tsx`, which the log window's bar shares; `window_manager.rs` mirrors the 48px); elsewhere it mounts `AppMenu` and `WindowControls`. **Only the two bars check the platform** (this one and `log-window/bar.tsx`) — not mounting `AppMenu` on macOS keeps its `Ctrl/Cmd+N`/`Q` from firing beside the native menu's. Every bar control is drawn through `app-bar/button.tsx` (`AppBarButton`, `AppBarGroup`/`AppBarDivider`); bar tokens are `--app-bar*` in `index.css`. The bar has no padding, so the close button reaches the corner.
- **`open_account_url` names the URL itself** — a host command that opened whatever the webview handed it would be an exfiltration channel.
- **The left sidebar** (`components/shell/left-sidebar/`, exporting the sidebar alone; `left-sidebar/sidebar.tsx`): the library's `SidebarProvider` owns `Cmd/Ctrl+B`; open/collapsed is controlled from the layout via `usePersistedFlag`, since the library's `sidebar_state` cookie is never read back. Open is `LeftSidebarCard` (drag-resizable), collapsed is `LeftSidebarPill` in the same footprint. **Narrowness is the provider's own `isMobile`, never a second media query** — `toggleSidebar` branches on it to flip `open` or `openMobile`, so a component using another rule flips a state nothing shows. Narrow, the toggle opens the card as a drawer over the content row (`relative` in `app-layout.tsx`); a scrim, Escape or any navigation closes it. The controls at the card's top (New chat, the namespace picker, both search boxes) wear `SIDEBAR_CONTROL_CLASS` (`src/lib/control-style.ts`): the chat composer's fill and border.
- **The drawer is `role="dialog" aria-modal`, held by `useFocusTrap`** (`src/lib/focus-trap.ts`). Both yield to an overlay opened inside it: the trap stands aside while its node sits under an `aria-hidden="true"` element, and the drawer's Escape listener is on `window`, after the `document` listener a dialog dismisses on, so one keypress closes the dialog alone.
- **The right sidebar** (`right-sidebar.tsx`) is a row item, taking width from the page. It has no fixed maximum: a drag stops where `<main>` reaches its floor, `min(320px, 50%)` of the row (`PAGE_MIN_WIDTH`). On a narrower window it shrinks to its minimum before `<main>` goes under that floor, leaving the stored width alone. `ResizeHandle` and `usePersistedWidth` (`src/lib/persisted-width.ts`) are shared with the left card. `RightSidebarToggle` is pinned to the content row's top-right corner, below the left drawer's scrim. Its state is `useRightSidebar` (`src/lib/right-sidebar.tsx`) — chrome, out of the URL, persisted **per mode** (open state and width); the layout supplies the mode, and `usePersistedWidth` re-reads when its key changes. **The `aside` does not scroll**; its contents own a scroller each.
- **The right sidebar's content**: on the dashboard the focused object (`ObjectPanel`), else `DashboardChat`; in chat mode the focused log view (`LogsViewPanel`, `components/logs/log-panel.tsx`) or a placeholder.

## Window frame

**The window frame is per-platform** (macOS native / Windows frameless-opaque / Linux frameless-transparent). `WindowFrame` (`components/primitives/window-frame.tsx`, at `__root.tsx`) paints Linux's border and shadow. `WindowResizeHandles` (`window-resize-handles.tsx`) is its **sibling**, never a child — the frame's `contain: paint` would clip it. `main.tsx` adds `<html class="frameless">` on Linux only. **Full-height screens use `min-h-(--app-min-h)`, never `min-h-svh`.** Maximized Linux goes full-bleed (`useWindowMaximized`). → [ADR: per-platform window chrome](../../../docs/adr/2026-08-09-per-platform-window-chrome.md).

Off macOS there is no native menu bar: `AppMenu` (`app-bar/menu.tsx`) owns `Ctrl/Cmd+N`/`Ctrl/Cmd+Q` and invokes `new_window`/`quit`; `WindowControls` (`window-controls.tsx`) draws the caption buttons. They wear the bar's hover wash, `APP_BAR_HOVER_CLASS`, which lives in `src/lib/control-style.ts` with the omnibox's `APP_BAR_CONTROL_CLASS`: the app bar imports `window-controls.tsx` and `context-omnibox/`, so neither imports anything from `app-bar/`.
