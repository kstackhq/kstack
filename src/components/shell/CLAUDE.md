# src/components/shell — the app's frame

The app bar, the mode rail, both sidebars, the window frame and its controls, the startup gate and `layouts/app-layout.tsx`. Also owns `src/lib/`'s `window-drag.ts`, `focus-trap.ts`, `persisted-width.ts`, `left-sidebar-width.ts` and `right-sidebar.tsx`. The webview-wide rules, security invariants first, are [`src/CLAUDE.md`](../../CLAUDE.md). **`context-omnibox/` (the bar's cluster chip) is described in the cluster guide** ([`../cluster/CLAUDE.md`](../cluster/CLAUDE.md)): open it before changing the omnibox.

## Startup

**`ReadyGate` (`src/components/shell/ready-gate.tsx`) draws `AppMark`** at 48px, centred, in every state. `AppMark` draws `src/assets/icons/`'s light or dark app icon, one per scheme; those are `make generate-icons`' copies of `src-icons/`. `index.html` carries a static copy of the same mark inside `#root`, so first paint and React's first commit show the same thing in the same place — keep them matching. It also draws a 56px `data-tauri-drag-region` strip over its top edge (the app bar's height), so the window drags before the app bar mounts; `index.html`'s static copy carries the same strip.

## Window layout

`layouts/app-layout.tsx` is the one place the shape is expressed: a 56px app bar over the mode rail beside the main card (left sidebar, `<main>`, right sidebar). The `SidebarProvider` column is the chrome (`bg-border`), around a rounded, bordered card. Nothing is fixed-positioned. → [ADR: the chrome holds the mode switch, the scope and the global actions](../../../docs/adr/2026-11-21-the-chrome-holds-the-mode-switch-the-scope-and-the-global-actions.md). Traps:

- **The app bar** (`components/shell/app-bar/`, exporting `AppBar` alone): the gutter (`TrafficLightGutter` or `AppMenu`, `HistoryNav`, `LeftSidebarToggle`), the cluster chip, the title (`title.tsx`: the chat's title, or the dashboard's breadcrumbs off `useDashboardNav`, all through `VisibleText`), then on the dashboard `NamespacePicker`, then `RightSidebarToggle` and, off macOS, `WindowControls`. **While the sidebar is open and the window wide, the gutter is the sidebar's width plus `PAGE_INSET`**, so its divider meets the page's edge. It is a `deep` Tauri drag region; both chips opt out with `data-tauri-drag-region="false"`. A press that drags never clicks, so `onPointerDown` (`dismissPopupsOnWindowDrag`, `src/lib/window-drag.ts`) clicks the pressed element itself to dismiss popups; `startsWindowDrag` mirrors Tauri's `drag.js`, so diff it on an upgrade. `window_manager.rs` mirrors the 56px, checked by a Rust test. **Only the two bars check the platform** (this and `log-window/bar.tsx`), which keeps `AppMenu`'s `Ctrl/Cmd+N`/`Q` off macOS. `transform-gpu` stops WebKitGTK's resize flash, so the bar paints `bg-border` itself. It has no padding, so the close button reaches the corner.
- **The mode rail** (`mode-rail/`, exporting `ModeRail` alone) is always mounted: the modes as router `Link`s in `<nav aria-label="View">`, Notifications and Settings at its foot.
- **`open_account_url` names the URL itself** — a host command that opened whatever the webview handed it would be an exfiltration channel.
- **The left sidebar** (`left-sidebar/`, exporting the sidebar alone): `SidebarProvider` owns `Cmd/Ctrl+B`; open/collapsed is the layout's `usePersistedFlag`, since the library's cookie is never read back. Open is `LeftSidebarCard` on the chrome's tint; collapsed, nothing. **`AppLayout` reads its width once (`useLeftSidebarWidth`) for the card and the bar**: a second reader would not see a drag live. **Narrowness is the provider's own `isMobile`, never a second media query** — `toggleSidebar` branches on it. Narrow, the toggle opens the card as a drawer over the main card (`relative`); a scrim, Escape or any navigation closes it. Controls at its top wear `SIDEBAR_CONTROL_CLASS` (`src/lib/control-style.ts`).
- **The drawer is `role="dialog" aria-modal`, held by `useFocusTrap`** (`src/lib/focus-trap.ts`). Both yield to an overlay opened inside it: the trap stands aside while its node sits under an `aria-hidden="true"` element, and the drawer's Escape listener is on `window`, after the `document` listener a dialog dismisses on, so one keypress closes the dialog alone.
- **The right sidebar** (`right-sidebar.tsx`) is the main card's last column, taking width from the page. It has no fixed maximum: a drag stops where `<main>` reaches its floor, `min(320px, 50%)` of the row (`PAGE_MIN_WIDTH`). On a narrower window it shrinks to its minimum before `<main>` goes under that floor, leaving the stored width alone. `ResizeHandle` and `usePersistedWidth` (`src/lib/persisted-width.ts`) are shared with the left card; its drag offsets by `CARD_INSET`. Its state is `useRightSidebar` (`src/lib/right-sidebar.tsx`) — chrome, out of the URL, persisted **per mode** (open state and width); the layout supplies the mode, and `usePersistedWidth` re-reads when its key changes. **The `aside` does not scroll**; its contents own a scroller each.
- **The right sidebar's content**: on the dashboard the focused object (`ObjectPanel`), else `DashboardChat`; in chat mode the focused log view (`LogsViewPanel`, `components/logs/log-panel.tsx`) or a placeholder.

## Window frame

**The window frame is per-platform** (macOS native / Windows frameless-opaque / Linux frameless-transparent). `WindowFrame` (`components/primitives/window-frame.tsx`, at `__root.tsx`) paints Linux's border and shadow. `WindowResizeHandles` (`window-resize-handles.tsx`) is its **sibling**, never a child — the frame's `contain: paint` would clip it. `main.tsx` adds `<html class="frameless">` on Linux only. **Full-height screens use `min-h-(--app-min-h)`, never `min-h-svh`.** Maximized Linux goes full-bleed (`useWindowMaximized`). → [ADR: per-platform window chrome](../../../docs/adr/2026-08-09-per-platform-window-chrome.md).

Off macOS there is no native menu bar: `AppMenu` (`app-bar/menu.tsx`) owns `Ctrl/Cmd+N`/`Ctrl/Cmd+Q` and invokes `new_window`/`quit`; `WindowControls` (`window-controls.tsx`) draws the caption buttons. They wear the bar's hover wash, `APP_BAR_HOVER_CLASS`, which lives in `src/lib/control-style.ts`: the app bar imports `window-controls.tsx` and `context-omnibox/`, and the mode rail wears it too, so none imports anything from `app-bar/`.
