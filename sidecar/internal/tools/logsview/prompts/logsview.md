## LogsView

Every LogsView call opens a live view of logs in the user's window, replacing the one they were looking at, and answers you one line saying what opened. You never see the lines, except those the user selects, which ride their question: to read logs yourself, run `kubectl logs` in Bash. Call it whenever the user asks to see, tail or search logs, and call it again to narrow or move the view.

A view shows one or more sources merged by timestamp, each a resource as `<kind>/<name>` in a namespace: a pod, or a deployment, statefulset, daemonset, job, cronjob or replicaset, whose pods the view follows as they come and go. A source opens whether or not it exists or has pods now, so a view can wait for one to start: the receipt says when a source has nothing to read yet, or is not in Kstack's cache of the cluster yet, and then check its name if it should be there. A source shows its default container, as `kubectl logs` does, unless `containers` names some or `all_containers` is set; the receipt names any container it left out. A pod source also shows what Kstack's log cache holds of the pod's earlier instances, and of a pod that is gone; the cache holds only what a view has read. A source with `previous` reads the instance before the last restart from the cluster, read or not, and it is finished: when the user asks why a pod restarted or crashed, open a view of its previous instance, and once the pod is running again, of the previous and the current as two sources. `filters` keeps only the lines from the nodes named, and `grep` keeps only the lines whose message matches the regular expression. `anchor` is where the view opens, and `pin_to_end` whether the viewer stays on the newest line as more arrive: "tail the logs" is `anchor: tail, pin_to_end: true`; "the last two minutes" is `anchor: 2m` alone.

A refusal is one JSON line. `{"error":"bad-input"}` names the `field` to change and, inside a source, its `source` index. `no-container` is a source that lacks a container named, with the `containers` it has; `too-many` a view of more than 100 containers, the most Kstack reads at once: filter it by node, or name fewer sources or containers, or single pods; `no-nodes` a filter by region, zone, os or arch on a cluster whose nodes Kstack cannot read: filter by node instead; `not-mirrored` a source of a kind Kstack's cache of the cluster does not hold, or, with no `source`, a cache holding no pods: use `kubectl logs` instead. `no-cache` and `syncing` mean the cluster cannot be checked yet: use `kubectl logs` meanwhile.
